## Lessons from the V1 round (do these again)
- **Process:**
  - Brainstorming: ask Matt quick, batched multiple-choice questions.
  - Write the spec and get Matt's OK.
  - Plan with a planning agent that verifies its code in a scratch worktree.
  - Build with subagent-driven development and two-stage reviews.
  - Matt then says to proceed on his own.
- **Reviews caught real bugs in most tasks:**
  - the save pinning the default scale;
  - camera snaps and spin;
  - leaf stacking and churn;
  - leaves sinking into the ground;
  - Classic regressions.

  Keep reviewers on, ask them to run probes, and fix Important findings before the next task.
- **The plan's code goes stale as fixes land.** Tell each implementer which files changed since
  the plan, and to compare test counts by difference, not by absolute numbers.
- **Matt is very sensitive to jitter.** For any motion (camera, leaves, worm), test frame-to-frame
  rotation, position and reversal, not only end states. Use a deterministic seed sweep, not one
  seed.
- **Classic is pinned by hash tests** (`propPlacement.test.ts`, `scaledProps.test.ts`), proven
  against Step 1a. New surface things go in their own meshes.
- **Settings:** store a value only when the player picks it, so a vote's new default reaches
  everyone else. Students who try every option end up pinned; plan for that before applying a
  vote that keeps more than one mode (CLAUDE.md).
- **Perf gates take about 35 minutes and need a quiet Mac:** one agent, nothing else running.
  Read-only reviews can run in parallel with an implementer by using a scratch git worktree.
- **One rebuild entry point** (`World.switchForest`) kept shader compiles at zero. Do the same
  for entering and leaving underground.
- `crawl.ts`, `main.ts` and `obstacles.ts` are over the ~260-line guide. Put the underground in
  its own module (`src/underground/`) rather than growing them.
